- `ui/@types/lichess/i18n.d.ts` is generated by `ui/.build/src/i18n.ts`; `parseXml` sorts keys with
  localeCompare, so hand-typed entries placed next to their site.xml neighbour are out of order.
  Grep the d.ts neighbours to check.
  **Why:** 7.6 claimed "typed in the build's format" but put keys after `timeAlmostUp`.
  **How to apply:** whenever a unit hand-edits i18n.d.ts.
- A new notify content type without a `ui/notify/src/renderers.ts` entry gets an empty bell entry
  (view.ts returns undefined). Check whether it's handed off to a later unit and disclosed.
- Read the decisions.md rows against the code: 7.6's row said the day alarm "still rings" when no
  proposal comes, but the ring check drops it as stale.
- CorresAlarm's ring deletes by `_id` after reading the game, so a concurrent upsert (toggle
  re-sync) can be wiped. lila has the same pattern; call it a nit unless new code makes it worse.
